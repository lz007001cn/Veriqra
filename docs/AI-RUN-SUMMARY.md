# AI 测试运行总结

## 使用方式

打开“测试运行”，查看一轮运行详情，点击“生成测试总结”。结果分为本轮概况、主要问题和后续建议，可复制，也可重新生成。总结仅保留在当前页面内存中，刷新或离开该运行会清除；需要留存时先点击“复制总结”。

进行中的运行可生成阶段性总结；已完成或取消的运行按照当前记录总结。生成内容只在当前页面展示，不修改测试结果、缺陷状态或数据库结构，也不作为运行完成/缺陷关闭动作。

## 生成依据

- 当前运行的名称、状态、环境、构建版本和创建/结束时间。
- 全量运行用例的最新结果：PASS、FAIL、BLOCKED、SKIPPED，以及尚无尝试的 NOT_RUN。
- 运行时冻结的用例定义、步骤、预期结果与最新实际结果/失败信息。
- 本轮失败尝试直接关联的缺陷，包括这些缺陷目前的状态、解决说明及更新时间；不混入项目的无关缺陷。

统计由服务端计算，AI 负责文字分析。已记录比例不等于通过率；历史失败不会因为缺陷后来关闭就被改写成通过。

运行时间和缺陷更新时间用于区分“当时的测试结果”与“之后的处理状态”。生成历史运行总结时，已关闭的缺陷应作为后续处理结果说明，不据此推断当前版本仍有同一故障。

为控制输入规模，详细证据最多取 40 条运行用例和 20 条关联缺陷，优先选择失败、阻塞和未执行用例，文本另有总预算。发生节选时页面提示；统计仍包含全量运行用例。

## 接口

`POST /api/projects/{projectId}/runs/{runId}/ai-summary`

```json
{"language":"zh-CN"}
```

`language` 支持 `zh-CN`、`en`。接口读取当前已保存数据，无需提交结果内容。具备当前项目读取权限的活跃用户可以生成。

响应包含：

- `input`：本次读取的运行基础信息、统计、证据及截取标志。
- `analysis.overview`：本轮概况。
- `analysis.findings`：主要问题/观察。
- `analysis.recommendations`：后续建议。
- `generatedAt`：本次生成时间；数据读取时间见 `input.capturedAt`。

## 实现

后端在一次事务中读取运行依据，释放数据库连接后调用现有 Vertex AI 提供者。复用外部 AI 配置和认证，不新增数据表。

前端在切换项目、运行或视图，以及本轮结果变化时清理旧上下文。重新生成失败时保留已有总结；请求结果不会串到其他运行。总结是生成时的数据快照，需要时可以重新生成。

配置沿用 `config/ai.local.properties` 或 `VERIQRA_AI_*`。开发构建和本地验证不自动更新 ECS。
