## 2. 需求文案

### ZS-R01：支持热更新缓存为空时的服务器切换

**优先级：HIGH；建议状态：ACTIVE。**

**标题：** 游戏更新或首次切服后，允许使用空热更新缓存完成服务器切换

**描述：**

> 用户故事：作为需要在国际服与国服官服之间切换的玩家，我希望在游戏更新后、尚未下载目标服热更新时仍能正常切服，也能在不启动游戏的情况下直接切回来源服。
>
> 背景：Persistent 下的 Blocks 是热更新覆盖层，基础资源在 StreamingAssets 中。覆盖层目录存在但没有文件，是合法状态；空覆盖层不能被当成客户端损坏。
>
> 验收条件：
> 1. 来源服存在有效非空热更新缓存时，能够完成切换并显示正确的目标服务器。
> 2. 来源服 Blocks 目录存在、文件数为 0 时，预检允许通过；切换完成后能够保存文件数为 0、字节数为 0 的有效缓存记录。
> 3. 首次切换到尚无热更新资源的目标服后，不启动游戏、不下载热更新，也能直接切回来源服；来源服原有热更新内容保持一致。
> 4. 空目录与目录缺失必须区分。切换所需活动目录缺失时，显示具体问题，不宣告切换成功，当前服务器保持原值。
> 5. Blocks 中存在未完成下载的 .tmp 文件时，提示下载未完成，不执行切换；完成下载后可以重新尝试。
>
> 范围：国际服与国服官服热更新缓存切换。B服渠道组件安装由 ZS-R02 描述。本需求不要求运行游戏验证登录账号。

**AI 补充生成要求：**

> 请生成 5 条中文测试用例，分别覆盖：非空缓存正常切换、合法空缓存切换、不启动目标游戏直接切回、活动目录缺失、存在未完成下载文件。每条包含前置条件、操作和可观察的预期结果。区分“应用按预期拒绝操作”与“测试失败”，不要假设空目录等于目录损坏。

### ZS-R02：发布包内置并正确应用 B服渠道组件

**优先级：HIGH；建议状态：ACTIVE。**

**标题：** 用户解压发布包后可直接使用受支持的 B服渠道组件

**描述：**

> 用户故事：作为使用 B服的玩家，我希望解压 ZZZSwitch 后即可使用当前支持的 B服渠道组件，不需要额外寻找框架文件或手动修补发布包。
>
> 验收条件：
> 1. 在没有旧 ZZZSwitch 缓存、没有外部 B服组件的环境中，官方发布包包含支持版本所需的 B服组件。程序首次识别受支持版本时能够完成组件准备，并显示可用状态。
> 2. 国服官服切换到 B服时，正确应用渠道组件；切回官服后渠道身份正确恢复，共用游戏基础资源保持一致。
> 3. 从 v1.3.6 起，对程序明确判定为兼容的后续游戏版本，可以复用已有 B服组件，并将目标客户端显示的版本信息同步到实际游戏版本。未声明兼容的版本不属于成功复用场景。
>
> 历史依据：v1.3.4 修复发布包缺少 B服框架文件；v1.3.6 补充跨版本复用和版本同步。游戏版本变化与 ZZZSwitch 软件升级分别记录，不能混为一个版本号。

### ZS-R03：正确展示应用更新状态与版本关系

**优先级：MEDIUM；建议状态：ACTIVE。**

**标题：** 在设置页检查稳定版更新并正确比较正式版与本地测试构建

**描述：**

> 用户故事：作为 ZZZSwitch 用户，我希望在设置页看到当前版本、最新稳定版本和更新说明，并且只有存在更新版本时才收到可更新提示。
>
> 验收条件：
> 1. 当前软件版本为 1.4.0、稳定版检查结果为 1.4.1 时，显示发现新版本及对应更新说明。
> 2. 当前版本与返回的稳定版本均为 1.4.0 时，显示已是最新版本，不提供无意义的同版本升级操作。
> 3. 在稳定通道中，本地测试构建 1.4.0-test.20261022+demo 与正式版 1.4.0 按相同核心版本比较，不误报同核心版本升级；若稳定版为 1.4.1，仍应提示可更新。该规则针对 test. 构建，不能扩展成忽略所有 beta／rc 预发布标记。
> 4. 检查更新超时或网络不可用时，显示检查失败及重试入口，不把失败显示为“已是最新版本”，其他本地功能仍可使用。
>
> 范围：本演示覆盖检查、展示与版本比较，不要求现场下载安装新版。通过固定更新响应和版本比较夹具复现边界输入，避免依赖 GitHub 当时的最新版本变化。

版本比较依据：[v1.4.0 的 UpdateVersion 实现](https://github.com/lz007001cn/ZZZSwitch/blob/v1.4.0/src/ZZZSwitch.Update/UpdateVersion.cs)。`1.4.0-test.20261022+demo` 是本材料定义的比较输入，不是声称曾发布过的安装包。

### ZS-R04：精简窗口与系统托盘保持一致的切服体验

**优先级：MEDIUM；建议状态：ACTIVE。**

**标题：** 精简窗口正确显示服务器、切换进度及托盘恢复状态

**描述：**

> 用户故事：作为只需要快速切服的玩家，我希望使用精简窗口完成操作，在关闭到托盘后能重新打开，并能清楚知道当前服务器与切换进度。
>
> 验收条件：
> 1. 打开精简窗口时，国际服、国服官服、B服入口可见，当前服务器只有一处高亮，且与实际客户端识别结果一致。
> 2. 开始切换后，在窗口内显示进度与最终结果；成功后当前服务器高亮更新为目标服，避免重复启动同一切换。
> 3. 关闭行为设置为隐藏到托盘、默认窗口为精简窗口时，关闭窗口不退出程序；左键单击托盘图标可恢复精简窗口，当前服务器显示保持一致。
>
> 历史依据：v1.3.2 引入托盘和精简窗口；后续版本继续改进窗口交互。
