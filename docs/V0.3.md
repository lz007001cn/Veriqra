# v0.3：AI 用例与 JUnit 导入

开发分支：`codex/v0.3.0-imports-ai`，版本：`0.3.0-SNAPSHOT`。本版复用现有 35 张表，无新增数据库迁移。

## AI 用例

将 `config/ai.example.properties` 复制为 `config/ai.local.properties`，填写 Google Cloud 项目、区域、模型和仓库外的服务账号 JSON 路径。示例默认使用 `global`、`gemini-2.5-flash`。启动应用时加载配置。

也可用 `VERIQRA_AI_CONFIG` 或 `-Dveriqra.ai.config` 选择其他配置文件；环境变量 `VERIQRA_AI_PROJECT`、`VERIQRA_AI_LOCATION`、`VERIQRA_AI_MODEL`、`VERIQRA_AI_CREDENTIALS` 优先于文件。

服务账号须能调用项目的 Vertex AI，项目已启用 `aiplatform.googleapis.com` 并关联结算。凭据无需上传到前端或放入 WAR。

操作：需求详情 → AI 生成用例 → 修改候选及步骤 → 勾选 → 保存为草稿。未勾选和舍弃的候选不入库。保存会同时创建用例、步骤和待复核需求关联；检查用例后使用已有就绪、关联复核和计划功能继续。

需求描述承载验收条件。生成不会占用数据库事务；保存按生成时的需求版本检查并整批提交。未配置、认证失败、超时、限流和不完整回答都有页面提示，可继续手工创建。

接口：

- `POST /api/projects/{project}/requirements/{requirement}/ai-cases/preview`：`{"instruction":"补充要求"}`。
- `POST /api/projects/{project}/requirements/{requirement}/ai-cases/accept`：`{"expectedVersion":0,"candidates":[...]}`，结构见预览返回。只发送选中的候选。

## JUnit 导入

自动化与导入页提供可下载的 `samples/junit-demo.xml`，包含正常、失败、跳过三条结果，统一 classname 为 `demo.LoginTest`。

选择文件并预览 → 按未知身份准备注册 → 分别映射到就绪用例 → 再次预览 → 填写运行名称并导入。沿用单 classname 限制。

导入记录可查看文件名、来源、SHA-256、请求编号、结果与对应 Run。Run 的“查看导入来源”返回该运行的导入记录。

提交前会将请求编号、文件指纹及表单信息保存在当前浏览器会话，按账号和项目区分。刷新后自动查询上次请求；结果不明确时，使用原文件和相同信息重试会复用原编号。查询或预览不重复创建 Run。

- `GET /api/projects/{project}/imports[?runId=...]`：项目或指定 Run 的记录。
- `GET /api/projects/{project}/imports/{id}`：导入、Run 快照和 Attempt 详情。
- `GET /api/projects/{project}/imports/requests/{uuid}`：按原请求编号找回结果。

## 本地验证

`mvn test`、`node --test src/test/js/*.test.js`；配置空测试库后运行相关 MySQL 集成测试。真实模型检查显式启用：`mvn -Dtest=VertexAiProviderTest -Dveriqra.ai.live=true test`。

部分 Windows JDK 需要设置短的 Unix socket 临时目录，例如 `-DargLine=-Djdk.net.unixdomain.tmpdir=C:/Temp`（目录须已存在）。这是本地测试参数。

候选验收和正式发布继续按开发计划执行；当前版本未部署到 ECS。
