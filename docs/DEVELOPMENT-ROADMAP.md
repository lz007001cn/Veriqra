# 期末展示开发与精简计划

更新：2026-10-27。v0.3.0 已于 10 月 22 日发布并部署 ECS，数据库沿用 35 表。当前开发版为 `0.9.0-SNAPSHOT`，完成期末展示打磨和功能精简；本批验证已完成，v0.9 尚未发布或部署。

## 目标与顺序

完成一个讲得清、可实际操作的期末展示项目：需求 → AI 辅助生成用例 → 测试计划 → 手工执行／JUnit 结果导入 → 缺陷 → 复测关闭 → 首页查看结果。

开发顺序：**v0.3.0 补齐导入与 AI → v0.9.0 展示打磨 → 最后做减法收尾，形成 v0.9 展示定稿**。先把展示主线做完整，再精简外围功能。

原 v0.4～v0.8 的扩展安排和 v1.0 路线由本计划替代。复杂报表、评论附件、站内通知、CI、执行调度和框架迁移不纳入本次期末交付。

## v0.3.0：导入体验与 AI 用例生成

### A. 补齐现有 JUnit 导入任务

- 提供导入记录和来源查询，从导入打开 Run，从 Run 找回来源。
- 将选择报告、预览、注册身份、确认映射、导入结果串成连续操作。
- 给出一份可直接演示的 PASS／FAIL／SKIPPED 样例和具体错误提示。
- 刷新或提交后断网时，能查询同一导入结果，避免重复创建 Run。
- 沿用当前支持格式，明确单 classname 限制；不扩展成通用报告兼容工程。

### B. 接入真实 AI，生成候选测试用例

用户操作：打开需求 → 点击“AI 生成用例” → 生成 3～5 条候选 → 编辑、勾选或舍弃 → 保存选中的用例 → 使用现有就绪操作进入后续测试。

最小实现范围：

1. 后端提供可替换的 `AiProvider` 接口，首个实现接入 Google Cloud Vertex AI；项目 ID、区域、模型名称和凭据文件路径通过后端配置接入。
2. 输入现有需求的标题、描述和验收条件，可附加一句生成要求。
3. 返回结构化候选：标题、描述、前置条件、优先级、操作步骤及预期结果，覆盖正常、异常和边界场景。
4. 用户可以逐项修改、选择和舍弃；选中项保存为现有 `DRAFT` 用例、步骤及待复核需求关联，继续使用原有就绪和关联复核动作。
5. 模型请求在数据库事务之外；选中批次统一保存，沿用需求版本校验。候选预览不新增长期业务表。
6. 未配置模型、超时、返回格式不正确时，页面给出简明反馈并允许重新生成，保留手工创建入口。

接入方式保持简单：先完成一家可用模型服务，不建设模型管理平台、Agent、RAG、计费或额外审批流程。

2026-10-22 已接入 Vertex AI 的 `global` 端点与 `gemini-2.5-flash` 模型；应用后端和页面已实现，完成真实生成、编辑、选择保存及用例就绪检查。凭据保留在仓库外。

完成标准：配置真实模型后能生成、编辑并保存候选；保存的用例可关联需求、加入计划并执行。用一份小报告完成预览、映射、导入和结果回看，刷新后仍能找到同一次导入。

## v0.9.0：期末展示打磨

v0.9.0 聚焦同一个展示项目，按以下顺序实施。已有 AI、主线跳转、首页数量汇总和 JUnit 示例继续复用。

| 顺序 | 开发内容 | 完成标准 |
| --- | --- | --- |
| 1. 操作主线 | 区分“搜索”与“创建”；保存后显示结果和明确的下一步；突出“从计划创建运行”“记录结果”“从失败创建缺陷”。将常驻角色说明、重复确认解释收为简短提示或按需说明，检查创建表单和成功提示随导航收起的已有修复 | 从需求进入用例、计划和运行时，每一步都能直接找到后续操作；不可执行的动作说明具体缺少什么 |
| 2. AI 与导入展示 | 需求详情明确标出生成依据；保留生成、编辑、选择、保存的连续操作。保存后直接打开已存用例或进入计划，清楚区分“手工新建”。导入沿用现有预览、映射、历史和来源链接，压缩说明 | 真实生成 3～5 条候选并保存选中项，页面不会使人误以为需要重新填写；JUnit 示例能导入并回看对应运行 |
| 3. 执行与缺陷闭环 | 执行页突出当前用例、结果提交和下一条；失败后带入上下文创建缺陷；缺陷页突出处理、标记已解决、复测、关闭及尚缺的条件 | 先提交 FAIL 并创建缺陷，处理后提交关联的后续 PASS，完成复测关闭，原始失败记录仍可回看 |
| 4. 首页与演示材料 | 首页精简为需求／用例数量、运行进度、未关闭缺陷及继续操作入口；把现有 ZZZSwitch 文案收为一条 5～8 分钟的操作脚本 | 使用 1 条需求、3～5 条用例、1 个计划、含 PASS／FAIL 的执行和 1 个闭环缺陷讲完整流程；额外展示一次 AI 与一次 JUnit 导入 |
| 5. 功能减法 | 按下一节迁移基础项目设置，裁撤小组任务、积分和冗余后台功能 | 核心页面、接口和导航保持连贯，退役模块的专属代码、文案、测试和说明同步清理 |

2026-10-24 首批已实现：空列表突出创建并隐藏搜索；有写权限时收起常驻角色说明；区分新建与编辑提示；AI 保存后提供已存用例和计划入口，并刷新需求覆盖；计划详情明确就绪与开跑动作；运行页提供填写结果、下一条和最新失败提缺陷入口。执行页先展示步骤，再填写结果，界面统一使用“测试结果／执行记录”等业务文案。

从原计划去创建或检查用例后，可返回原计划并明确点击加入该用例，避免误建第二个计划。开发分支为 `codex/v0.9.0-demo`，版本为 `0.9.0-SNAPSHOT`。

2026-10-25 第二批已实现：AI 面板显示来源需求编号、标题与生成依据，候选详情可展开；缺陷页按状态突出处理、解决、复测和关闭，解决说明前移，支持原运行复测或新建修复版运行；打开当前用例后可直接返回原缺陷。正在提交时显示保存进度，只有无法确认结果时才显示恢复操作。

独立模拟项目已用浏览器完成原始 FAIL → 创建缺陷 → 开始处理 → 解决说明 → 新运行 PASS → 关联复测 → 关闭，原始失败保留。演示脚本同步把 JUnit 导入安排在最终复测 PASS 之前。本批继续完成首页汇总与外围模块精简。

2026-10-25 第三批已实现：首页保留需求数、用例数、当前运行进度与未关闭缺陷，提供六个主线入口；成员与负责人迁入项目设置；小组、任务、转交、积分与排行的专属页面、API、服务和测试删除；后台仅保留用户维护，部署元数据接口继续使用。同步清理旧审核报告与退役文案。现有数据库结构和业务数据保留，本批不需要升级 DDL。

2026-10-27 本批已接入 ECharts 6.0.0 和 Bootstrap Table 1.24.2，组件随 WAR 本地打包。首页突出所选运行的结果记录进度、失败／阻塞用例、项目未关闭缺陷及有效需求覆盖；需求／用例总数作为辅助信息，异常项可进入对应执行记录或缺陷。用户维护支持服务端全量搜索、角色／状态筛选、排序和分页，保留新增、编辑与密码重置。

主线保留已有用例／计划就绪、需求覆盖、执行快照和复测关系；页面用简短的业务语言表达这些状态，不自动跳过必要的业务动作。

## 最后阶段：精简功能，完成展示定稿

此阶段安排在上述展示打磨之后，属于 v0.9.0 的收尾工作。

| 处理 | 范围 | 做法 |
| --- | --- | --- |
| 保留 | 登录、基础用户维护、项目与基础成员管理 | 提供测试者与开发者的必要入口，后台收为少量页面 |
| 保留 | 需求、用例／步骤、关联覆盖、计划、执行／历史、缺陷复测 | 保留展示主链和真实业务关系，简化页面操作 |
| 保留 | AI 候选用例、基础 JUnit 导入、简洁首页 | 作为期末展示亮点和结果入口 |
| 移出展示并裁撤 | 团队任务、转交、独立任务验收、积分转账／奖励、贡献排行 | 先移除入口，再清理专属代码、接口、装配和测试 |
| 收缩 | 管理后台的安全页、会话页、访问／登录／审计记录界面和重复统计 | 展示入口只保留必要用户维护；实际共享代码按依赖整理 |
| 删除 | 已退役模块的专用脚本、重复说明、无用样例与文案 | 直接清理，不为本次精简再建报告和审查工程 |
| 后置处理 | 现有非核心数据库表和历史数据 | 在代码依赖移除后逐项判断，展示前不做批量 DROP |

精简顺序：

1. 把协作页承载的基础项目成员、项目角色和负责人配置迁到项目设置，修正创建项目后的入口。缺陷指派继续使用基础项目成员。
2. 简化导航和页面，先使展示界面只出现核心功能。
3. 去除用户创建时自动建立积分账户的耦合，再删除任务、小组、转交、积分、奖励和排行等外围模块；同步清理启动装配、路由、双语文案和对应测试。
4. 检查主线，保留用例／计划就绪、执行快照、Attempt 历史、JUnit 映射及缺陷复测依赖。
5. 最后评估非核心表与数据的处理；按实际变动补迁移或安装说明。

保留一个可回看的 v0.3.0 正式版本，再进行减法。最终展示定稿继续归于 v0.9 系列，不展开新的大版本路线。
